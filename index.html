Weather point

Each building carries coordinates and altitude, so the valley station and the summit get separate forecasts. One hourly server-side fetch feeds every screen.

Limits, not rules

The complex sets its own thresholds — gusts at the summit station, snow per day, fog, deep cold. Crossing one raises a warning, never a cancellation.

People decide

Staff press “cancel for weather”. The system then does the dull part: it drops the bookings, voids the charges with the reason, and prints the list of guests to call.

How a void is stored

The charge row is never touched. A void is a separate insert in charge_voids holding the charge id, the user, the UTC timestamp, a reason code and a note. A charge counts toward the balance and the reports only when it has no void row.

charge_voids charge_id chg_7f31 voided_by usr_bauer_m (manager) voided_at 2026-02-14T13:12:44Z reason_code weather note "gusts 94 km/h at 2,600 m"
Why the outlets stay honest

Outlet revenue is read from charge lines, never from payments. The cash report is read from payments, never from charges. A bill split between card and cash touches no outlet total, and a weather void removes exactly one outlet's line. Every figure traces back to a row with an id, a user and a timestamp.

Tax is a snapshot on each line — rate id, rate in basis points, net, tax and gross, all in cents. When a government changes a rate, last winter's invoices stay exactly as they were printed.

Three groups, three behaviours

Own — shuttle, taxi, car, bicycle, motorbike: vehicles, drivers, trips, seats. Lifts — cable car, gondola, chairlift, funicular, elevator: status, hours, passes charged to room. External — plane, train, metro, coach: recorded on the reservation, and it produces the pickup.

07 — How it is built Next.js · NestJS · PostgreSQL

Boring where it has to be boring.

Tenant isolation

Postgres row-level security. Every request runs in a transaction that opens with set_config('app.tenant_id', $1, true) — transaction-local, so it cannot survive on a pooled connection. Policies read current_setting('app.tenant_id', true); a missing setting returns null and the query sees nothing, so a mistake fails closed.

Money

Integer cents, never floats. charges, payments and charge_voids are insert-only, and the application's database role holds no UPDATE or DELETE on them. The rule lives in the database, not in the UI.

Tax

A rate table per complex. Every line stores a snapshot: rate id, basis points, net, tax, gross. Half board posts two lines — accommodation at 10% and meals at 10% — so the invoice splits VAT correctly. Lift passes sit at 13%, drinks and services at 20%.

Weather

One hourly server job per weather point against api.met.no with a proper User-Agent, cached and shared. Maps are Leaflet on OpenStreetMap tiles. No keys, no paid tier, nothing that starts charging in month three.

Hosting

Ubuntu 24.04, no Docker. Its own Linux user, its own database, its own port, its own Nginx server block. PM2 keeps it up. Nightly pg_dump, seven kept, one restore tested before handover.
